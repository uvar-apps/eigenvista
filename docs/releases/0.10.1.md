# EigenVista 0.10.1 — smoother lighting, larger calculations

Prepared 18 November 2026. This patch release corrects the lighting artifacts
reported in [#91](https://github.com/uvar-apps/eigenvista/issues/91) and removes
the artificial memory ceilings tracked in
[#92](https://github.com/uvar-apps/eigenvista/issues/92). Release preparation and
delivery are tracked in [#93](https://github.com/uvar-apps/eigenvista/issues/93).
The source update, rebuilt redistributables and publication are being prepared;
this document does not yet certify a published 0.10.1 package.

## Smooth shading as you move around a molecule

One camera-aligned headlight and neutral ambient fill replace the six-light rig
that produced gray bands and repeated, polka-dot highlights. Atoms, bonds,
built-in molecular and quantum surfaces, and sampled-field raycasting share
the same view-relative illumination. Orbiting or rolling the view keeps the
lighting consistent, while the shape remains readable. Glossy surface shading
uses one restrained highlight; molecular ambient occlusion retains its matte
Lambert shading and contact-depth effect.

## Use the available memory

EigenVista attempts the requested allocation instead of rejecting work against
an estimated application memory allowance. This applies to SES/SAS molecular
surfaces, quantum grids and meshes, imported structures and fields, saved
documents, conversion queues, annotations, numerical field inspection and the
external AI connection. GUI users and connected agents follow the same policy.

- Requested SES spacing is preserved. An exact occupied-cell neighbor index
  avoids allocating empty spatial cells without changing the requested
  resolution or omitting atoms.
- Grid presets remain convenient starting points. Custom resolutions accept
  safe integer dimensions of at least two; an operation is no longer refused
  solely because it exceeds a fixed application sample or mesh count.
- Critical buffers allocate fallibly, with checked size arithmetic. Recoverable
  allocation failures and cancellation retain the previous accepted result.
  Malformed input, invalid references and actual runtime/format/device
  representation limits still produce explicit errors.
- BinaryCIF parsing, transform decoding and cleanup use iterative traversal,
  including deeply nested input, without an artificial nesting allowance.
- Saved geometry, orbital batches, import warnings and connector-visible
  diagnostics are retained completely. Viewport images and quantitative field
  keys use the actual device resolution instead of fixed pixel ceilings.

This does not make memory unlimited. WASM32 has a finite address space, buffers
and file fields have actual integer representations, and graphics hardware has
texture and index capabilities. An operating system, browser or driver may
terminate a process after overcommitting memory; such termination cannot always
be caught and reported. Save important work before very large calculations.
See the [allocation policy](../allocation-policy.md) for the precise contract.

## Full 1AON surface and cache verification

The complete 1AON structure, **58,870 atoms**, was used to qualify a solvent-excluded
surface with Alvarez radii, a 1.4 Å probe and the requested 0.5 Å grid spacing.
It produced **2,091,126 vertices and 4,182,788 triangles**. The native app,
Chromium and WebKit rendered the result and saved/reopened its cache with
matching geometry, source hash, area, volume, connected components and cavities.
The document's inflated contents exceed the former 128 MiB allowance. Reopening
the cached mesh did not require recalculating the surface.

These are measured results for this input and configuration, not a universal
molecule-size or memory guarantee.

## Native Save and background work

Native Save transfers complete encoded archives as raw binary, avoiding the
expansion of each byte into a JSON number. The document format and public
browser save result remain compatible. Source-file protection, scoped access,
atomic/no-clobber saves, cancellation and dirty-document tracking remain in place.
Native processing has no imposed default completion deadline; progressing
transfers have no total-duration allowance. Socket inactivity checks and an
explicit caller-selected deadline remain separate.

On macOS 14 and newer, the desktop shell disables WebKit's inactive scheduling
throttle. A real native acceptance run saved and reopened the large 1AON cache
while an AppKit probe confirmed the application was inactive and nonhidden.
Hidden/minimized/occluded-window operation remains unqualified: macOS rejected
the automated hiding attempt, and inactivity alone does not establish that
case. Older systems may ignore the scheduling setting. It does not prevent
system sleep or process termination.

## Keep interaction responsive

Candidate geometry, instance data and textures are uploaded and checked before
replacing the accepted scene, using zero-count staging instead of rendering the
entire candidate molecule twice. GPU allocation checks run at scene, size,
upload, AO-allocation and image-export boundaries. Ordinary camera/damping frames
avoid the new synchronous error queries, and AO caches its context capability.
Existing physical viewport/scissor restoration and context-loss handling remain.

## Compatibility and qualification

The document profiles, scientific source hashes, dependency/toolchain pins and
icon/logo are unchanged. Existing supported files and cached results remain
readable; the supported scientific import profiles have not been broadened.

Before the 0.10.1 version update, the included corrections passed local macOS
27/Apple Silicon qualification: **365 workspace Rust tests, 13 desktop tests,
23 packaging/connector checks and all 678 application browser cases** (339 per
engine), with zero browser failures, skips, flaky cases or retries. All 419
frozen source/input hashes matched before and after the browser suite. The
camera-query regression passed with AO both enabled and disabled; the original
large-protein test deadlines and scientific/pixel/source assertions were retained.
The native inspection harness exercised **34 methods through 179 calls and six
PNGs**, including the large cache save/reopen. The exact-upstream SES harness
passed 276 test executions with zero failures and six preexisting ignored
executions. These source-correction results are distinct from the final release
build and extracted-package acceptance, which must be recorded after packaging.

Linux, clean-Mac/Gatekeeper installation, the full supported macOS range and
universal out-of-memory recovery remain unqualified. See the
[handoff](../handoff.md) and [status](../status.md) for the current release-build,
package and delivery evidence.

## Release-source verification

The final 0.10.1 source also passes fresh local macOS 27 arm64 verification:
365 workspace Rust tests, 13 desktop tests, strict Clippy/formatting,
WASM/TypeScript/production and native debug builds, 23 packaging checks,
and all 678 browser cases. Each engine ran 339 cases with no failures, skips,
flaky cases or retries; all 419 frozen source/input hashes stayed unchanged.
Both engines repeated full 1AON generation and large cache save/reopen,
including image export from the reopened mesh. This is source qualification;
actual optimized-package acceptance and publication are recorded after packaging.
