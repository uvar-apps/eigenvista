# EigenVista 0.10.2 — clearer interaction and live scientific feedback

Release preparation is tracked by
[#98](https://github.com/uvar-apps/eigenvista/issues/98). This patch packages the
accepted interaction improvements in #94–#97. Local release qualification,
rebuilt-package identity and publication are recorded in the living
[handoff](../handoff.md) and [status](../status.md); a source version alone does
not establish that a downloadable package has been rebuilt or published.

## Find actions and see what you selected

Action buttons now stand out from surrounding labels with a tinted fill,
stronger border, bold text and subtle elevation. Disabled actions remain visibly
muted, and keyboard focus has a clear outline. Tabs, disclosure headings and
orbital rows retain their existing flat presentation
([#94](https://github.com/uvar-apps/eigenvista/issues/94)).

Selected atoms have gold hollow reticles. With selection picking off, an ordinary
click shows a cyan ring at the inspected atom, or at both endpoints of an
inspected bond, without replacing your selection. Gold takes precedence for
atoms already selected. The markers remain readable as you zoom, preserve the
element palette, respect visibility filters, and appear in exported PNGs.
**Clear selection** removes both cues; opening a new source resets them
([#96](https://github.com/uvar-apps/eigenvista/issues/96)). These are source-position
cues, including behind other geometry, rather than atom or surface outlines.

## Move a quantitative plane without a separate recompute step

Creating a plane keeps its sampling editor open with **Auto-update plane**
enabled. A spinner step, its arrow keys, an orientation change, or **Enter**
after typing a sampling value updates the existing plane. Typed drafts alone
do not start calculations. Rapid committed changes use the newest valid
definition. The previous complete plane and contours stay visible while the
replacement is prepared, and accepted colors, contours and resolution are
preserved unless you change them
([#95](https://github.com/uvar-apps/eigenvista/issues/95)).

**Cancel plane update** stops the editor's current update. **Cancel editing**
also stops pending automatic work. Hide Tools or collapse the widget to keep
the calculation running. Turn automatic updates off when you prefer to edit
several settings before choosing **Recompute analysis**. Invalid values and
recoverable errors retain the accepted result. Changing coordinate display
units alone does not resample the field.

## Follow molecular-surface generation

SES/SAS generation shows a readable phase and elapsed time in both the surface
controls and a compact viewport activity card. During mesh generation, the bar
shows actual completed/total blocks and a percentage for that phase. Other
phases show activity without inventing an overall completion percentage or
remaining-time estimate. The bar may restart as the phase changes
([#97](https://github.com/uvar-apps/eigenvista/issues/97)).

Progress and **Cancel calculation** remain visible with Tools hidden or Zen
mode enabled. Cancellation, source replacement and failure clear current
activity; cancellation and recoverable failure retain the previous accepted
surface. A phase reaching 100% does not mean the full job has finished: display
transfer and validation can follow meshing.

## The same workflows through the AI connector

The Mac app bundles its connection helper, launcher, portable instructions,
examples and palettes. Codex, Claude Code, Pi, OpenCode and generic local agents
use the same accepted selections, scientific jobs, caches and exports as the GUI.
No source checkout, compiler, embedded AI console or separate model account is
required to use an installed connector-enabled app.

Ask for outcomes in ordinary language, for example:

- “Select these atoms and show me which ones are selected.”
- “Move this plane half an angstrom along Z, keeping its contours and colors.”
- “How is the molecular surface coming along?”
- “Cancel this calculation and keep the previous surface.”

The agent handles capability discovery, owned job receipts and completion.
For technical clients, plane replacement supports optional `supersede:true`
on `analysis.create`, while molecular-surface status retains stage-local job
counts and adds active elapsed-time metadata through `app.state`. Older apps
may lack these additions. Pane placement and Zen remain GUI preferences.
See the [connector guide](../ai-connector.md) and
[technical API reference](../application-control.md).

## Retained features and compatibility

Version 0.10.2 retains 0.10.1's camera-relative headlight and neutral fill,
matte Lambert molecular ambient occlusion, and allocation-driven workloads.
Requested SES spacing and quantum grid dimensions are preserved; no artificial
application memory allowance or silent coarsening is introduced. The four-tab
resizable workspace, molecular representations, custom shaders, transparent PNGs,
scientific inspection, automatic display bonds and supported import profiles
remain available.

These interaction changes do not change scientific evaluators, mesh provenance,
scalar units, saved-document formats, dependency/toolchain pins or the logo.
Cached geometry and numerical field results remain portable in `.eigenvista`
documents. Preserve the immutable 0.10.1 and older tags and redistributables.

## Package and qualification boundaries

The redistributable target is an experimental **Apple Silicon Mac** app with
its converter and AI connector. The tester package is ad-hoc signed, not
Apple-notarized. First launch may require the per-app **Open Anyway** exception;
see [installation](../user-guide.md). The deployment target is macOS 13, but
all versions in that range and clean-Mac/Gatekeeper installation are not yet
qualified. Linux, Windows and Intel Mac packages are not available.

Allocation failures are reported where recoverable. WASM address space,
integer representations and actual GPU capabilities still apply; an operating
system, browser or graphics driver can terminate a process after overcommit.
Such termination cannot always be caught. Save important work before very large
calculations. Read the [allocation policy](../allocation-policy.md).

Source qualification passes 378 Rust workspace tests, 13 explicit desktop tests,
fmt/strict Clippy, WASM/TypeScript/production/native-debug builds, 23 packaging/
connector checks and all 720 Chromium/WebKit cases, 360 per engine, with no
failures, skips, flaky cases or retries and all 427 runtime/test/input hashes
unchanged. Version, citation and source-stage website checks pass. Actual clean
optimized-package rebuilding, extracted app/helper operation, signatures, cache
Save/reopen, PNG review and public release/site readback remain separate delivery
gates. Exact commands, package bytes/SHA-256, source identity and remaining gaps
belong in the living delivery records linked above.
