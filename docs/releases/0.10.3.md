## Save the completed inspection state

Save now refuses while an inspection edit is being prepared or applied,
with a message to wait for completion and try again. This covers molecular
surface appearance, measurements and labels, and committed quantitative-plane
changes during definition preparation and their brief update delay. Rapid
coalesced edits remain pending until the complete GUI operation settles;
simply typing an uncommitted draft does not block Save
([#99](https://github.com/uvar-apps/eigenvista/issues/99)).

Save and Quit follows the same coordination, including before the unsaved
marker has had time to redraw. The shared API and AI connector observe the
same pending state. A failed, cancelled or stale edit retains the last accepted
document and releases the pending operation; review the error before saving.
This prevents a successful-looking Save from silently omitting an edit that
has not finished. The original published 0.10.2 package predates this correction.

## Choose explicit replacement for ExFAT exports

The standalone converter adds **`--replace`**. It stages and publishes a complete
file atomically, permitting replacement of a destination that already exists
or appears while conversion is running. This option enables exports on the
tested Mac ExFAT volume, whose driver rejects hard links and exclusive rename
([#100](https://github.com/uvar-apps/eigenvista/issues/100)).

For example, after choosing an output that may intentionally be replaced:

```sh
eigenvista-convert calculation.molden --output calculation.eigenvista --replace
```

Use the default mode and a new filename when replacement is not intended.
The default continues to refuse overwrites and reports unsupported publication
on the tested ExFAT driver, even for a new destination. Existing **`--force`**
keeps its earlier permission for outputs found during preflight; it does not
grant replacement for an initially absent destination. **`--replace`** cannot
be combined with **`--force`** or **`--check`**. Inputs, their aliases, symlinks
and colliding batch destinations remain protected. Completed outputs survive
later conversion failures.

The installed AI connector offers the same explicitly selected replacement for
native documents, PNG images and CSV tables. Tell your agent which output may
be replaced, for example:

> Save the updated figure on my ExFAT drive. You may replace the existing
> result.png at that destination.

The agent checks the connected application's support and handles the export.
Fresh filenames remain the default; a general request to save a result does
not grant replacement permission. Browser downloads have no file-replacement
mode. Older app/helper pairs may lack this option.

This is qualification of the tested Mac driver, not a claim about every volume
or platform. Permissions policy is unchanged, and atomic publication is not a
power-loss recovery guarantee. Broader permissions, durability and platform
research remains in [#41](https://github.com/uvar-apps/eigenvista/issues/41).
See the [converter guide](../molden-import.md) for complete usage.

## Try the Accessible elements palette

The optional **Accessible elements** palette uses dark carbon, blue nitrogen
and vermilion oxygen, with selected Okabe–Ito hues and supplementary shades
for other common atoms. It overrides exactly **14 elements**: H, C, N, O, F,
Mg, P, S, Cl, Ca, Fe, Zn, Br and I. The other **104** retain their built-in colors
([#72](https://github.com/uvar-apps/eigenvista/issues/72)).

The package includes `accessible-elements.json` in its **Palettes/** directory
and in the app's bundled AI connector **palettes/** directory. Choose
**Appearance → Atom colours → Colours file…**, then select the file. For a
biological structure, use **Coloring → Element** to show element colors.
**Reset to defaults** restores the original palette. Palette choices remain
session preferences and do not change scientific data or saved molecular files.

An agent can load the same file without a separate GUI step. For example:

> Load Accessible elements, use element coloring, turn on ambient occlusion,
> and save a transparent PNG of this molecule.

The [palette guide](../../palettes/README.md) and
[design evaluation](../design/2026-11-20-accessibility-palette.md) document exact
mappings, attribution and rendered comparisons with the default, Muted and
Pastel palettes on water and full 1AON. The evaluation includes ordinary/AO
rendering, three color-vision simulations and grayscale. Those diagnostics
support the common-element design goal; they do not establish universal
accessibility. Some supplemental element pairs and grayscale distinctions
remain ambiguous. Use picking or labels to confirm identity.

The original 0.10.2 ZIP predates the additional file, but its existing loader
can use the [palette download](https://uvar-apps.github.io/eigenvista/downloads/accessible-elements.json).
MatterViz Muted/Pastel and the built-in default remain available unchanged.

## Retained features and compatibility

Version 0.10.3 retains automatic plane updates, visible picking cues, live
molecular-surface progress, the four-tab resizable tools pane and Zen mode,
molecular representations, matte Lambert ambient occlusion, custom surface
shaders and transparent PNG export. Requested quantum grid dimensions and
SES spacing remain allocation-driven, with no artificial memory allowance or
silent reduction of detail.

Scientific evaluators, f64 source data, mesh provenance, scalar units,
saved-document formats, dependency/toolchain pins and the logo are unchanged.
Cached geometry and numerical results remain portable in `.eigenvista`
documents. Preserve the immutable 0.10.2 and older tags and redistributables.

## Package and qualification boundaries

The redistributable target remains an experimental **Apple Silicon Mac** app,
converter and bundled AI connector. The package is ad-hoc signed, not
Apple-notarized. First launch may require the per-app **Open Anyway** exception;
see [installation](../user-guide.md). The deployment target is macOS 13, but
clean-Mac/Gatekeeper installation and the entire OS range remain unqualified.
Linux, Windows and Intel Mac packages are not available.
