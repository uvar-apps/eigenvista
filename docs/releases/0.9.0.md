# EigenVista 0.9.0 — scientific inspection

**Unreleased.** Prepared 16 November 2026 on `codex/scientific-inspection`,
awaiting user testing before a pull request or merge. Application, library,
converter, connector and website source metadata identify 0.9.0. The latest
published download remains [0.8.0](https://github.com/uvar-apps/eigenvista/releases/tag/v0.8.0);
there are no published 0.9.0 packages or version DOI yet.

The annotated local `v0.9.0` tag records the development checkpoint authorized
on 16 November 2026. It does not mark a GitHub release or a merge into main.

## Select, measure and annotate

- Select original atoms and particular ligand copies; retain ordered picks for
  distances, angles and signed torsions.
- Keep named selections, editable labels and measurement monitors in native
  documents. Include annotations in normal and transparent PNG exports.
- Find atom-center neighbors within an explicit radius, optionally expanding
  complete residues. Save the neighborhood and retain its query provenance
  through renaming and reopening.
- Export measurement tables as CSV. Coincident or singular geometry has an
  explicit value or undefined explanation rather than an invented result.

## Molecular shape

- Generate solvent-excluded and solvent-accessible surfaces (SES/SAS) from
  coordinates, with explicit Bondi/Mantina or Alvarez radii, overrides, probe
  size and spacing.
- Calculate the whole source or an isolated selected subset, in the background
  with progress and cancellation.
- Change saved-surface color and opacity immediately, without an Apply button
  or regenerating geometry. Rename surfaces separately.
- Adjust visibility and surface shaders independently; save the
  cached mesh with its source, radii, engine and precision information.
- Keep cavities and requested spacing. Resource failures retain accepted results
  instead of silently coarsening the mesh. Atom/bond ambient occlusion remains
  separate from molecular-surface shading.
- Balance scene illumination with six equally strong, symmetrically placed
  camera-following lights, avoiding a dark back side when orbiting. Built-in
  mesh and raycast lighting share the arrangement; custom shaders retain their
  declared lighting.

## Put numbers on fields

- Read analytic orbital/density values or interpolate original Gaussian cube
  samples using f64 probes, true two-dimensional planes and line profiles.
- Build coordinate-aligned or three-atom planes; show contours, continuous
  numerical keys, signed ranges and supported display-unit conversions.
- Preserve raw values, coordinates, masks and scientific provenance in native
  caches and CSV exports. Outside-domain samples remain explicitly missing.
- Keep unknown cube meanings/units unspecified until the user declares them.
  Numerical analysis is independent of the 3D preview resolution.
- Fixed ranges clip interpolated values and profile segments correctly;
  contour saddle decisions remain robust across extreme finite value ranges.

## AI access and saved files

All new operations are available through the shared application controller and
bundled external AI connector, including discovery, edits, readback,
cancellation, exports and save/reopen. Codex, Claude Code, Pi, OpenCode and other
local coding agents can use the installed helper without a source checkout.
The [connector guide](../ai-connector.md) covers setup; the website contains
natural-language tutorials for the new workflows.

Existing native documents remain readable. Files containing the new inspection
records require a matching reader; 0.8.0 explicitly rejects their new required
capabilities. Authoritative quantum sources and legacy field hashes are
preserved. Camera, palette, background, AO and custom shader choices remain
session settings; save molecular data and export presentation figures separately.

## Qualification and delivery

The feature implementation passed complete local macOS validation before this
version-preparation change: 336 default Rust tests, eight desktop tests, strict
Clippy/build checks, 604 Chromium/WebKit application cases, 162 website cases,
packaging/source audits and all 34 new connector operations through 160 calls
against an extracted test app. That test package identifies itself as 0.8.0
and remains an unchanged historical artifact. Version preparation has also
passed fresh locked Rust/desktop tests, strict Clippy, production build,
version consistency, CLI version output, citation schema, packaging-support
checks and all 162 website browser cases. Subsequent user-test corrections add
live molecular-surface appearance and balanced camera-relative lighting. Their
final source passes **614 application browser cases** and **162 website cases**
in Chromium/WebKit, plus focused independent lighting/color/depth checks,
TypeScript and a production Vite build. Current artifact boundaries are recorded
in [status](../status.md) and [handoff](../handoff.md); those results do not imply
a rebuilt native tester package or a published 0.9.0 binary.

Qualification is local macOS only; Linux awaits the planned local hosts.
The icon/logo, compiler/dependency pins, frozen fixtures and scientific file
profiles are unchanged. Existing memory/native-file budgets remain in force.
Version-specific citation details will be added when the new DOI is supplied;
the current citation uses the project's concept DOI.
