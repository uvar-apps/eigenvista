Files, conversion, and saving.

Open an existing calculation or structure, inspect the import report, and save a self-contained .eigenvista document. Opening never overwrites the input. Keep original files: the preview deliberately imports a selected, supported subset rather than every source annotation.

Open and check a file

  1. Choose Open in the app's top bar, then select a supported local file. Use this button: Finder file associations and drag-and-drop loading are not implemented.
  2. If prompted about unsaved work, save or deliberately discard it before replacing the scene.
  3. Check atom, bond, basis, and field counts in Molecular data and Quantum fields. Read Import report and Provenance, including warnings.
  4. Use Fit scene if necessary. Imported structures show automatic display bonds; cube fields normally start in Volume preview.
  5. Choose Save and a new .eigenvista filename to retain the imported data and subsequent changes.

External imports start unsaved. A malformed-file error leaves the previous document intact. A valid grid that exceeds rendering precision can still open and remain savable with a preview error; see grid precision. The installed app performs these local workflows without an internet connection.

For a small structure check, download water.xyz: it should show 3 atoms and 2 bonds. For quantum fields, try water.molden; for a sampled field, try signed-affine.cube.

For biological selection, identities, and omitted annotations, see structure import policy. For exact accepted cube features and what a sampled field means, see cube fields.

Per-format byte limits include 32 MiB PDB text and 64 MiB text mmCIF/cube. BinaryCIF has separate 64 MiB expanded-payload and expanded-text limits. These sit inside broader numerical, atom, bond, and allocation bounds; they are rejection limits, not a promise that the largest accepted file will be interactive. See resource bounds.

Molden wavefunctions and density interpretation

A supported Molden input supplies one [Atoms] section with explicit AU or Angs units, one [GTO] basis, and real orbitals in one or more [MO] sections. Missing geometry/basis, ambiguous repeated sections, unsupported shell conventions, or invalid coefficients are errors. The reader does not repair an unrecognized producer convention by guessing.

Imported orbital labels include supplied symmetry information. Energies use hartree. Missing energies or occupations remain missing; an explicit Alpha/Beta spin is required by the Molden profile. One Alpha-only set is interpreted and reported as spatial orbitals with occupations up to two. Mixed Alpha/Beta sets retain their spin labels with occupations up to one; fractional occupations are preserved.

Where the density comes from

If every listed orbital has an occupation, the importer constructs the occupation-weighted density from those listed coefficients. A spatial set provides a total-kind matrix; a mixed Alpha/Beta set additionally provides alpha, beta, total, and alpha-minus-beta spin matrices. A beta-only set remains beta-only. If any occupation is missing, no derived density is created.

Fields labelled Occupation-derived … (listed orbitals) describe the listed export. They are not recovered correlated, transition, or independent difference density matrices. A truncated orbital set can produce only a partial density; omitted orbitals and ECP core electrons are not recovered.

Zero-occupation virtual orbitals remain fully validated, listed, renderable, and savable. They contribute zero to the derived density. A fractional nonzero occupation contributes its supplied value. The initial field is the last source-order orbital with positive occupation, or the first orbital if none qualifies; unusual ordering means this is not necessarily the highest-energy orbital.

ORCA exports

Export a Molden file with ORCA's orca_2mkl before opening it. Preserve the producer title/marker: it selects the normalization convention. The qualified subset currently accepts S, P, and spherical 5D shells; ORCA SP, Cartesian D, F, and G are rejected. This is not a claim of support for every ORCA version or option. Do not remove a producer marker to bypass rejection.

Frequency, normal-mode, optimization-trajectory, charge, and core/ECP sections are not preserved as structured data. Ignored sections are named in the report. Keep the original calculation. A supported file needs no installed Python, ORCA, or other calculation program to be read.

The downloadable water example is a calculated RHF wavefunction with 24 basis functions, 24 spatial orbitals, and a total density. Follow the orbital tutorial to inspect it.

Read import warnings and provenance

The import report summarizes what was accepted and what needs attention. Provenance retains source information and decisions in the native document: original input name and byte checksum, importer/profile identification, bond method, warnings, and reported omissions. A checksum identifies source bytes; it is not a certification that the source's chemistry is correct. The source file itself is not embedded wholesale.

For structures, look for model/alternate selection, omitted zero-occupancy or unknown-element rows, missing/ambiguous identities, secondary-structure notices, and connection decisions. mmCIF/BinaryCIF declared connections retain deposited references, type/order, resolved selected endpoints, and retained/duplicate/omitted status. Cell/symmetry information is reported without creating symmetry mates. A compressed BinaryCIF checksum identifies the actual compressed input bytes.

All supported imports compute display bonds automatically. PDB CONECT and supported mmCIF covalent, disulfide, and metal declarations take precedence and are supplemented by coordinate-based connections. Rods represent display connectivity; they do not establish bond order, aromaticity, hydrogen bonds, oxidation state, or chemical validity.

When opening an older native document, missing display bonds may be added while preserving existing connections, scientific arrays, and meshes. The addition is reported and the document becomes unsaved. Save explicitly to retain the change; Open leaves the original untouched.

Convert files without replacing the scene

  1. Choose Convert files. The separate Convert Files window leaves the current scene open.
  2. Add supported input files and click Convert. The queue accepts at most 32 files.
  3. Review each row's report. A failed row shows its own error and does not discard successful results.
  4. Click a successful row's Save. Desktop Save opens a destination dialog; browser Save requests a download. Conversion alone writes nothing.
  5. Save or clear completed results before adding more work. Retained outputs together are bounded to 128 MiB.

Cancel stops that queue's pending work and retains completed results. Closing the conversion window preserves them in memory; Clear discards them. Saved/downloaded result bytes are released. Unwritten results do not survive closing the application. Conversion preserves supplied fields and existing native meshes but does not generate new surfaces.

Save, reopen, and share

Save creates a self-contained .eigenvista file containing selected structure and biological identities when available, bonds, supplied analytic fields or original sampled grids, provenance, saved surface geometry and generation metadata, visibility, colors, opacity, and global representation. A matching preview installation can show saved meshes without the original inputs or recalculation.

  1. Generate any meshes you want to keep, check visibility and appearance, and choose Save.
  2. On desktop, choose a destination. Cancelling leaves the document unsaved. In a browser, confirm the requested download completed.
  3. Reopen the saved file with Open. Existing meshes start in Isosurface mesh mode. The camera, active render mode, and session preferences are not restored.
  4. Share that file with another compatible preview installation. Keep the original input and a backup because the preview schema is not frozen.

Save does not export back to Molden, PDB, XYZ, mmCIF, or cube. There is no separate OBJ-plus-metadata export or external mesh linking. There is no automatic background saving, undo for surface deletion, or crash recovery. Use different native filenames to preserve multiple isovalues of the same field; regenerating replaces that field's meshes.

Compatibility and filesystem details

Older Rust-preview .molekel files open without a manual migration. Native Save also accepts that suffix, but new saves contain EigenVista identifiers regardless of filename and are not guaranteed to open in earlier Molekel builds. Native files containing biological identities require an application that supports the biological-structure feature. Keep an original when older software must continue to read it.

Desktop Save publishes a complete replacement file. On the tested APFS volume, replacing an existing file sets permissions to 0600 (owner read/write). Atomic replacement does not establish recovery after a crash or power loss. A CLI-created new file can fail with “operation not supported” on ExFAT; create it on APFS and copy the completed output. Desktop replacement Save uses a different path and succeeded on the tested ExFAT image. Other filesystem/platform behavior is not broadly qualified.

Leaving the application

Desktop close/quit checks for unsaved changes, unfinished operations, and converted results awaiting Save. Choose Cancel to continue working, Discard and Quit to cancel work and leave without saving, or Save and Quit to save the current document before leaving. Failed or cancelled saves keep the document open. Review a refreshed prompt if the document changes while it is displayed. Finish/cancel an existing native save first; save converted results from their queue. Save and Quit is unavailable while the queue has unfinished or unsaved work.

Browsers use their own close warning. Confirm all downloads before closing. When sharing the application, forward the complete tester ZIP with licenses, notices, and Source.

Command-line converter

The tester ZIP contains Tools/eigenvista-convert. The following examples assume it is on your PATH. Create output directories first. The converter supports the same input profiles as Open, including mmCIF/BinaryCIF and cube.

eigenvista-convert calculation.molden
eigenvista-convert calculation.molden.input --output calculation.eigenvista
eigenvista-convert --output-dir converted water.molden structure.cif
eigenvista-convert --check --json calculation.cube
eigenvista-convert --help

A single input defaults to a sibling .eigenvista output; multiple inputs require --output-dir. --output (or -o) chooses one destination. --check validates and reports without writing. --json writes per-file results, counts, warnings, and errors as an array on standard output; otherwise summaries go to standard error. Use -- before filenames beginning with a hyphen.

Existing outputs need explicit --force; an input can never be its own destination. The converter rejects colliding destinations and output symlinks. New outputs use no-clobber publication even with force, and require filesystem hard-link support; unsupported publication is an error, not a partial-write fallback. At most 256 inputs are processed sequentially. Later per-file failures retain successful outputs.

Exit status is 0 for complete success, 1 for a per-file import/write failure, and 2 for invalid options or path preflight errors. Conversion creates no new meshes. Open its output in the app, generate surfaces, and Save when you need portable geometry.
