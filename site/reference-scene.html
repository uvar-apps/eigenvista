03.2 / EIGENVISTA FIELD MANUAL

Scene, appearance, and images.

This guide follows EigenVista 0.10.6. Use the four tabs in the single Tools pane: Molecule, Fields, Surfaces and Appearance. The 0.10.6 Mac package includes this workspace and all the scientific-inspection tools described here. Find your way around the current workspace →

Frame a molecule, choose how atoms and fields are drawn, then export the current viewport. Global representation and field colors/opacity belong to the document. Camera, background, lighting choices, palettes, and shaders are display preferences for the session.

Molecular representations

Choose Representation in Molecule → Molecular data. The global choice is saved with the document.

ChoiceDepiction and use
Ball and stickAtoms and connecting rods; useful for checking a small structure and its display connectivity.
LiquoriceA rod-focused atomic view for inspecting connected molecular detail.
Van der WaalsSpace-filling atom spheres; no bond cylinders. Useful with ambient occlusion for dense molecules.
Protein backbone traceA path through supported protein backbone points.
Protein smooth tubeA smoother tube following the supported backbone.
Protein ribbonOriented protein ribbons where deposited identities and backbone geometry permit.
Protein cartoonHelical ribbons, strand arrows, and connecting loops based on deposited secondary assignments.

Protein choices require suitable biological identities. Nonprotein components retain atomic detail; chain/component overrides can mix styles. Missing atoms and gaps break protein paths rather than inventing a connection. See protein depiction rules.

Element colors cover atomic numbers 1–118. Display radii use published van der Waals tables where available and a covalent-radius-based continuation for Fm–Og; they are visual models. Automatic bonds use a separate covalent-radius heuristic. A drawn rod is not a bond-order or chemical-validity result.

Field colors, opacity, and surface shading

Under Appearance, Positive and Negative choose signed field colors, and Opacity controls field transparency. These apply across quantum/imported-field surfaces, not just the selected field, and are retained when saved. Molecular SES/SAS has its own live saved color and opacity under Surfaces → Molecular surfaces. Appearance edits do not recompute either field or geometry.

Surface shading offers Diffuse (the default) and Blinn-Phong (specular highlights on saved meshes and sampled raycast isosurfaces). It is a session preference, separate from atom/bond materials, and is not stored in the molecular document. Choose the rendering mode under Field rendering.

A single camera-aligned light and neutral fill give a smooth shape gradient as you orbit, pan or roll. Every viewing direction uses the same lighting, without opposing-light bands or repeated highlight spots. Atoms, bonds, protein depictions and built-in mesh/raycast surfaces share this arrangement. Blinn-Phong adds one coherent specular highlight; Diffuse keeps the built-in surface matte. Custom shaders keep their declared lighting; volume compositing stays unlit.

In Surfaces → Saved surfaces, the eye icon toggles one mesh's visibility and the trash icon removes it. There is no undo. Save to retain those changes. In sampled modes, the active field's meshes are visually replaced by the sampled display; eye/trash controls still manage saved meshes. Return to Isosurface mesh to inspect their effect independently.

Molecular ambient occlusion

Ambient occlusion emphasizes atom contacts and broad recesses in dense molecules. It starts off. While enabled with nonzero strength, atoms and bonds use Lambert shading plus screen-space ambient occlusion (SSAO), without specular highlights.

  1. For space-filling detail, choose Representation → Van der Waals.
  2. For best results, download matterviz-pastel.json and load it through Appearance → Atom colours → Colours file…. For a biological structure, choose Coloring → Element to see that palette.
  3. Under Appearance, enable Atom and bond ambient occlusion. Adjust AO strength from 0–100%; zero restores the normal molecular view.
  4. Leave Automatic AO radius checked initially. Read the chosen neighborhood in AO radius (angstrom).
  5. To tune the scale, uncheck Automatic AO radius. The manual slider starts at the current automatic radius and covers 0.25–50 Å in quarter-angstrom steps. Smaller radii emphasize nearby contacts; larger radii emphasize broader recesses.

For a molecular surface, expand the saved SES or SAS in Surfaces → Molecular surfaces and set its opacity to 1. Use built-in shading and enable Molecular surface ambient occlusion in Appearance. This separate switch uses matte Lambert shading to bring out pockets and clefts. See the 1AON surface comparison.

Automatic radius is derived from the atom-coordinate extent. Molecular surfaces use a wider neighborhood than atoms and bonds. With both switches active, the readout shows both radii. Manual mode uses one radius. Camera movement can change the visible screen-space effect while the radius stays fixed.

AO uses the visible scene to emphasize contacts and recesses. Offscreen geometry is not included. Turn it off if navigation becomes slow.

AO controls last through Open within the session; restart/reload begins with AO off. PNG exports include the current shading. Atom colors and picking still work. Each switch affects its own visible geometry. Quantum fields, custom shaders and protein depictions keep their materials. Turning AO off releases its image buffers. If enhancement fails, a message appears and normal rendering stays available; disable/re-enable to retry. A lost graphics context requires reload/restart.

Atom colours

The Appearance → Atom colours widget identifies Built-in default (118 elements) or the palette file loaded this session. Colours file… opens a JSON palette. Reset to defaults restores the bundled colors. Biological Coloring → Element displays these element overrides; other biological color modes use their own legends.

Two optional MatterViz palettes are supplied: Pastel is lighter with pale-pink oxygen and is recommended for AO; Muted has subdued colors with dusty-rose oxygen. They also live in the source checkout's palettes/ and tester ZIP's Palettes/. Both cover elements 1–109; 110–118 keep built-in defaults. Their upstream MIT notice accompanies the examples.

Accessible elements is an optional alternative evaluated with color-vision simulations. It changes H, C, N, O, F, Mg, P, S, Cl, Ca, Fe, Zn, Br and I; the other 104 elements keep their built-in colors. Load the file with Colours file…, then use Coloring → Element. The blue nitrogen and orange oxygen depart from conventional CPK colors. Some element pairs remain ambiguous; pick atoms to read their identities. Read the coverage and evaluation notes. Version 0.10.3 includes the file in its Palettes/ folder and bundled connector resources. The download also works with the older 0.10.2 palette loader.

Write a partial palette

{
  "format": "eigenvista-atom-colors",
  "version": 1,
  "colors": [
    { "z": 6, "symbol": "C", "color": "#ff00aa" }
  ]
}

z (atomic number) selects the element. The optional symbol is checked as a typo guard; it never selects an element. Partial palettes are supported: unlisted elements keep defaults. Colors must be lowercase #rrggbb.

The entire file is rejected for a wrong format/version, missing or empty colors, duplicate/out-of-range atomic numbers, an invalid color, or a symbol inconsistent with its atomic number. The current palette remains intact on rejection. Palette changes are session-only and do not make the molecular document unsaved; a fresh session uses the built-in palette.

Background and PNG exports

In the scene toolbar, Background color opens a color picker. The initial color is #e8edef; Reset background color restores it. The choice is session-only and is not written into molecular files.

  1. Frame the view, adjust lighting/appearance, and wait for any requested field calculation to finish.
  2. Choose Export image for eigenvista-view.png with the selected opaque background.
  3. Or choose Export image with transparent background for eigenvista-view-transparent.png. Empty areas are transparent; antialiased edges and translucent surfaces retain fractional alpha.
  4. Confirm the download completed, then open the PNG in an image viewer or place the transparent version on your intended background.

Both actions capture the current rendered viewport after zooming, resizing, or an idle period. Toolbar/status overlays are excluded. Exports additionally include scientific labels, measurement monitors and visible numerical keys in normal and transparent images. Transparent export leaves the selected background visible in the app. Exports include the current field mode and AO; they are images, not saved scientific documents. Use Save separately to retain data.

If an export fails, its error appears without changing the molecular document; try the export again. PNG files use the app or browser’s download mechanism. Check that the file has finished downloading before closing the window.

Custom surface shaders

See the illustrated shader guide for X-ray and cutaway views, downloadable presets and a complete worked example.

The Appearance → Surface shader widget optionally replaces built-in surface materials with a vertex/fragment GLSL pair. It affects surfaces, not atom/bond AO. Shader sources and uniform values last for the session and are not stored in .eigenvista.

  1. Choose a Vertex shader and a Fragment shader file. The picker accepts .vert, .frag, .glsl, or text files.
  2. Optionally load a Parameters file (.params) with default uniform values.
  3. Choose Apply to: all surfaces or one saved surface.
  4. Click Apply shader. Parsed uniforms appear as live controls. Their edits redraw immediately. Choosing new source files leaves the previous applied pair active until you apply the new pair.
  5. Use Save parameters to export the current uniforms as a Molekel-style .params file. Desktop opens a save dialog; the browser downloads it. Cancelling is harmless; a write error appears in the panel.
  6. Use Clear shader to restore Diffuse/Blinn-Phong, clear loaded files/parameters, and reset shader transparency.

Examples are included in the tester/source packages under Shaders/; repository examples also live in app/shaders/ and shaders/. Classic GLSL 1.x built-ins such as ftransform(), gl_Vertex, gl_Normal, and gl_Color are mapped onto the current rendering environment. Surface colors feed gl_Color.

Parameters and validation

Matching uniform types retain their values when new sources load; changed types reset to defaults. A parameter file with a nonnumeric value, unsupported/mismatched kind, or wrong component count is rejected with its parameter name and line number, preserving current values and the applied shader. Clear before loading another pair when shared uniform types conflict. Parameter export uses lines such as float name<TAB>value and writes a complete replacement file.

Transparency and errors

Shader transparency starts checked and blends visible fragments in depth order, even when document opacity is 100%. Uncheck it to force opaque output. The setting updates an applied shader live and lasts for the session. Clear shader resets it to checked.

Compile/link errors appear in red in the panel after Apply. Correct and reapply the pair, or Clear shader to restore built-in materials. Transparent objects use ordinary object sorting; intersecting layers can show ordering artifacts.
